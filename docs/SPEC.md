# Как работать с прототипом

Документ для разработчиков и дизайнеров: как устроен прототип, как его читать, менять и проверять. Что собрано из макетов и чего нет — в `project/Coverage.dc.html` (доска «Покрытие макетов»).

## 1. Что это

Прототип SmartBackOffice «Умная очередь» на дизайн-системе Альфа-Банка. Это не боевой код: данные вымышленные, бэкенда нет, события сервера имитируются таймерами. Прототип показывает поведение и состояния экранов. Если прототип и макет в Figma расходятся, правду говорит макет; исключения перечислены в разделе 6.

## 2. Как открыть

```bash
python3 -m http.server 8791 --directory project
```

- Весь продукт в сборе: `http://127.0.0.1:8791/Main.dc.html`. Отсюда работает вся навигация.
- Отдельное состояние: `http://127.0.0.1:8791/<Имя-доски>.dc.html`, например `Task-embed-timeout.dc.html`.

Открывать файлы двойным кликом (`file://`) нельзя: компоненты подгружают друг друга по HTTP.

## 3. Структура

```
project/
  canvas.json            раскладка досок по страницам канваса
  support.js             рантайм формата .dc.html
  ds/alfa-bank/          tokens.css и сборка компонентов дизайн-системы
  *.dc.html              компоненты и доски
tests/                   автотесты
docs/SPEC.md             этот документ
```

### Компоненты

| Файл | Что это |
|---|---|
| `Main` | Список задач и корень приложения: держит текущий раздел, открытую задачу и карточку, общий стек уведомлений |
| `Task` | Окно задачи: шапка задачи и клиента, панель «Окно задачи» со встройкой РК, история изменений |
| `ClientSearch` | Клиенты: «Мои» и поиск |
| `ClientCard` | Карточка клиента со вкладками и шторками |
| `Refs` | Справочники |
| `PinnedEmployees`, `PinSheet` | Закрепление: страница «Закреплённые сотрудники» и общая шторка «Заменить / Добавить / Открепить сотрудника» |
| `ModuleSearch`, `ModuleReports` | Валютный контроль: поиск по модулю и отчёты |
| `CreateTask` | Форма создания задачи |
| `Header` | Шапка: «Назад», общий поиск, виджет звонков, профиль |
| `SideMenu` | Левое меню и меню «Создать» |
| `TaskScreen`, `ClientsPage`, `ClientCardPage`, `CreatePage`, `ModuleSearchPage`, `ModuleReportsPage` | Обёртки «компонент + меню + шапка» для досок |

### Доски

Доска — маленький файл, который подключает компонент с конкретными пропсами и показывает одно состояние. Имена по префиксам: `Task-*`, `Card-*`, `Clients-*`, `Ref-*`, `Create-*`, `Reports-*`, `Hold-*`, `Take-*`, `Close-*`, `Header*`, `SideMenu*`.

Страницы канваса (`canvas.json → pages`): Список задач, Клиенты, Карточка клиента, Окно задачи, Навигация, Поиск по модулю, Общие компоненты, Справочники.

## 4. Формат `.dc.html`

Каждый файл — разметка в `<x-dc>` и класс логики в `<script type="text/x-dc">`.

```html
<x-dc>
  <helmet><style>/* стили компонента */</style></helmet>
  <sc-if value="{{hasRows}}" hint-placeholder-val="{{true}}">
    <sc-for list="{{rows}}" as="r" hint-placeholder-count="5">
      <button onClick="{{r.open}}">{{r.title}}</button>
    </sc-for>
  </sc-if>
  <dc-import name="Header" back="{{yes}}" on-back="{{goBack}}"></dc-import>
  <x-import component-from-global-scope="DesignSystem_88b1f8.Tooltip" content="{{tip}}">…</x-import>
</x-dc>
<script type="text/x-dc" data-dc-script data-props='{"status":{"editor":"enum","options":["work","done"],"default":"work"}}'>
class Component extends DCLogic {
  renderVals() { return { rows: [], hasRows: false }; }
}
</script>
```

- `{{имя}}` — значение из `renderVals()`. В разметке нет выражений: всё, включая строки для `aria-*` и обработчики, готовится в `renderVals()`.
- `<sc-if>` и `<sc-for>` — условие и цикл. Атрибуты `hint-*` нужны только редактору канваса.
- `<dc-import name="X">` — другой компонент проекта. Пропсы пишутся через дефис (`ready-timeout`), обработчики — `on-…`. Атрибут `name` занят под имя компонента, пропс с таким именем передать нельзя.
- `<x-import component-from-global-scope="DesignSystem_88b1f8.X">` — компонент дизайн-системы.
- `data-props` описывает пропсы для редактора; `$preview` задаёт размер превью.
- Состояние — `this.setState(...)`, чтение — `this.state`. В компонентах для этого есть помощник `st() { return this.state || {}; }`.

## 5. Связь между компонентами

Компоненты общаются событиями на `window`, чтобы не тянуть пропсы через все уровни.

| Событие или функция | Данные | Кто слушает | Зачем |
|---|---|---|---|
| `sbo:call` | `{ num, who }` | `Header` | Начать звонок в виджете шапки. Звонок всегда один, отдельных панелей звонка на страницах нет |
| `sbo:back` | `{ id, label, fn }` | `Header` | Положить шаг в стек кнопки «Назад» |
| `sbo:ref` | `{ id }` | `Main` | Открыть справочник |
| `sbo:create` | `{ kind }` | `Main` | Начать создание задачи |
| `sbo:pin` | `{ mode: 'replace' \| 'add' \| 'remove', clients: [имена], current }` | `PinSheet` (внутри `Header`) | Открыть шторку закрепления сотрудника за клиентом, одиночно или группой |
| `sbo:pin-done` | `{ mode, clients, employee }` | `PinnedEmployees`, `ClientCard` | Закрепление отправлено: строки показывают «Закрепление / Открепление в процессе», через 5 с — итог |
| `window.__sboToast(m, { kind, text, badge })` | — | `Main` | Показать уведомление в общем стеке |
| `window.__sboCallReady` | — | — | Флаг: виджет звонков в шапке готов принимать `sbo:call` |

## 6. Общие правила интерфейса

Правила действуют на всех страницах. Подробно, с примерами — на доске `TableStandard.dc.html`.

1. **Поиск.** Любой поиск начинается с первого символа и сразу, первый результат подсвечен, Enter открывает его.
2. **Модалки.** Любая модалка — шторка справа: на всю высоту, отступ 8 px, ширина 500 px, выезжает справа, закрывается по Esc. Выпадающие меню и поповеры модалками не считаются.
3. **Ховеры.** Реакция на наведение и тултипы начинаются через 0,3 с. Уход курсора, нажатие и фокус с клавиатуры — без задержки.
4. **Поиск по модулю ВК** открывается только кнопкой «Поиск в ВК» в поле поиска шапки; в левом меню отдельного пункта «Поиск» нет, в группе «Валютный контроль» остались «Отчёты» и внешние ссылки.
4a. **«Назад».** Кнопка только в шапке. Ведёт в предыдущий раздел, если он был, иначе на раздел выше.
5. **Уведомления.** Общий стек, максимум три, по одному каждого типа. Уведомления о новых задачах показываются только на странице задач.
6. **Таблицы.** Единый топбар над каждой таблицей: слева «Всего N» (когда выбраны строки — «Выбрано N») и «Выбрать все» / «Снять выбор» (где строки можно выбирать), справа «Обновить» (иконка), разделитель, «Настройки» (где они есть) и «Скачать таблицу». Внизу — пагинация и «Показывать по N»; когда выбраны строки, нижняя панель превращается в панель действий: чекбокс с числом выбранных (нажатие снимает выбор), действия, пагинация справа. Так в очереди и в клиентах. По 10 строк на страницу. Стили топбара — блок `ТОПБАР ТАБЛИЦЫ` (классы `tb-*`), одинаковый во всех компонентах с таблицами. Заголовок прилипает под шапку и всегда с нижней границей. Нижняя панель прилипает к низу экрана.
7. **Закреплённое поверх контента.** Шапка страницы и заголовок таблицы делят одну общую размытую подложку. Сверху её фон ровно цвет страницы (`--bg-base-secondary`), над таблицей он плавно переходит в белый (`--bg-base-primary`) к заголовку. Ширина белой части — ровно по белой карточке таблицы, поля по бокам остаются серыми. Нижние панели таблиц и низ меню — фейд с прогрессивным блюром, цвет подложки `--color-light-neutral-translucent-400-inverted`. Жёстких плашек с границей быть не должно.
8. **Иконки.** Только SVG, эмодзи не используются.
9. **Карточка клиента.** Правая колонка (звонки, избранный контакт, закреплённый сотрудник) не выше карточки слева. Если звонков много, колонка скроллится внутри, а снизу уходит в фейд — только пока ниже есть что прокрутить.
10. **Окно задачи.** Высота панели — экран минус шапка минус 24 px снизу. При прокрутке панель наезжает на карточку задачи и встаёт под шапку, дальше скроллится только встройка. Разделы «Задача» и «Клиент» в шапке одной высоты.
11. **Чекбоксы в строках** стоят по центру первой строки текста ячейки — во всех размерах таблицы.

Где прототип намеренно отличается от макетов: поиск с первого символа, модалки звонка шторкой справа вместо центра, общий поиск в шапке шире клиентов и задач.

## 7. Встройка РК в окне задачи

Имитирует протокол из спеки (раздел 6.11.1 и «Страница задачи. Встроенная задача РК»). Управляется пропсами `Task`:

| Пропс | Значения | Что показывает |
|---|---|---|
| `embed` | `''`, `loading`, `timeout`, `not-found`, `network`, `internal` | Обычная загрузка, вечный скелетон, таймаут готовности, три ошибки из белого списка |
| `readyTimeout` | миллисекунды, по умолчанию 10000 | Сколько ждать готовности встройки |
| `pending` | да/нет | Плашки «Данные скоро загрузятся» после создания задачи |
| `headless` | да/нет | Только окно задачи без шапки (тикета в УО нет) |

Поведение: «Сохранить» в форме даёт уведомление «Задача сохранена»; «Обновить» спрашивает «Обновить без сохранения?», если сохранения не было дольше 10 с и статус не финальный.

Отличие от спеки, которое нужно учесть в реализации: «Выйти без сохранения?» в прототипе появляется, только если в окне что-то меняли. По спеке — всегда, когда с последнего сохранения прошло больше 10 с.

## 8. Как вносить изменения

### Поменять поведение или вид

Правьте компонент (`Task.dc.html`, `Main.dc.html` и так далее). Доски подхватят изменение сами.

### Добавить состояние

1. Если нужно, добавьте пропс в компонент и в его обёртку (`TaskScreen` и подобные), опишите в `data-props`.
2. Скопируйте похожую доску, поменяйте `<title>` и пропсы в `<dc-import>`.
3. Добавьте запись в `canvas.json`:

```json
"Task-my-state.dc.html": { "expand": "fill", "w": 1440, "h": 900, "x": 0, "y": 0,
  "is_interactive": true, "page": "task", "title": "Моё состояние" }
```

и имя файла в массив `order`.

### Добавить стиль с `:hover`

После правки перегенерируйте правило паузы:

```bash
python3 tests/tools/hover.py project
```

Скрипт собирает все `:hover`-правила файла и дописывает блок `HOVER-DELAY`. Руками этот блок не правят. Новый компонент нужно добавить в список `FILES` в скрипте.

### Проверить синтаксис логики

```bash
python3 - <<'EOF'
import re, subprocess
s = open('project/Task.dc.html', encoding='utf-8').read()
open('/tmp/c.js', 'w').write(re.search(r'<script type="text/x-dc"[^>]*>(.*?)</script>', s, re.S).group(1))
subprocess.run(['node', '--check', '/tmp/c.js'])
EOF
```

## 9. Тесты

Нужны Node 22+ и Google Chrome на macOS. Тесты поднимают локальный сервер на порту 8792 и headless Chrome с отладочным портом 9333.

```bash
tests/run-all.sh                      # всё: наборы, смоук, автотест очереди
tests/shots.sh Main.dc.html out.png   # поднять сервер и браузер, снять скриншот доски
node tests/embedtest.mjs tests/qa     # один набор (сервер и браузер уже подняты)
```

| Набор | Что проверяет |
|---|---|
| `autotest` (через `run-autotest.sh`) | Очередь: тултипы, фильтры, колонки, закреплённые ячейки во всех размерах и режимах |
| `uitest`, `taskflow`, `navtest`, `opentest` | Очередь, окно задачи, навигация, общий поиск, «Назад», открытие карточек |
| `clienttest`, `cstest`, `cardtest`, `refstest`, `reportstest` | Клиенты и чекбоксы, карточка клиента, справочники, отчёты |
| `embedtest`, `createtest` | Встройка РК, размер окна задачи, путь создания задачи |
| `modaltest`, `hovertest` | Шторки справа, пауза 0,3 с |
| `notifytest`, `livecalltest`, `stucktest` | Уведомления, поток звонков, общий блюр шапки |
| `smoke` | Каждая доска из `canvas.json` рендерится без ошибок |

Что нужно знать:

- Полный прогон идёт около часа, смоук — самая долгая часть. В обычной работе запускайте только наборы по изменённым экранам, смоук — перед передачей.
- Тестовый рантайм не выполняет таймеры с задержкой от 5,9 до 12,1 с. В демо-досках, которые должны сработать под тестом, берите другие значения (поэтому у `Task-embed-timeout` таймаут 4500 мс).
- Тесты читают отложенные ховеры и тултипы, поэтому перед проверкой ждут не меньше 0,5 с.
- Пути в скриптах после переноса в репозиторий поправлены, но прогон из репозитория не проверялся. Если что-то не стартует, первым делом смотрите путь к `project/` в начале скрипта.

## 10. Канвас

Прототип живёт в канвасе claude.ai Design. Репозиторий — его копия на момент коммита. В канвасе файлы могут править и в редакторе, поэтому перед выкладкой изменений из репозитория нужно забрать живые версии изменяемых файлов и слить правки, а не затирать их.

## 11. Что не собрано

Виджет задач, страница звонка и архив звонков, списки задач кредитования, вариант 2 встройки ВК, админка. Данные везде вымышленные. Точное значение токена `--color-light-neutral-translucent-400-inverted` нужно взять из дизайн-системы: в локальных токенах его нет, стоит запасной цвет.
